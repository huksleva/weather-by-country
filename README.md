# Weather by Country

Решение тестового задания на Python. Программа загружает города из файла,
получает текущую погоду через `https://wttr.in/{City}?format=j1`, выводит
температуру каждого города и рассчитывает статистику по странам.

## Запуск

Нужны Python 3.10 или новее и доступ к интернету. Установка пакетов не требуется:
используется только стандартная библиотека Python, для JSON — модуль `json`.

Откройте терминал в папке проекта:

```console
python main.py
```

На Windows вместо `python` можно использовать `py`.
По умолчанию читается `cities.txt`, расположенный рядом с `main.py`.
Для другого файла или настройки запросов:

```console
python main.py my-cities.txt --timeout 20 --attempts 3
```

Формат входного файла: UTF-8, один город на строку. Поддерживается UTF-8 BOM.
Пустые строки игнорируются; пробелы по краям удаляются. Повторы сравниваются
без учёта регистра, при этом сохраняются первое написание и порядок городов.
Исходный `cities.txt` содержит все 8 городов из файла задания:
[второй источник](https://gistpad.com/raw/vk-task-14),
[основной источник](https://cloud.mail.ru/public/LWcw/kpMqFgztw).

## Как работает решение

1. `load_cities` читает весь файл в память и удаляет повторяющиеся города.
2. `fetch_weather` последовательно запрашивает каждый уникальный город.
   Имя города кодируется для URL, поэтому пробелы и кириллица поддерживаются.
3. `parse_weather` создаёт модель `WeatherData` с полями `city`,
   `temperature_c` и `country`. Температура берётся из
   `current_condition[0].temp_C`, страна — из
   `nearest_area[0].country[0].value`. Название города сохраняется из файла:
   `nearest_area` иногда указывает ближайшую станцию, а не запрошенный город.
4. Для каждой страны `country_statistics` вычисляет количество городов,
   среднее арифметическое, минимум и максимум текущих температур.
   Страны выводятся по алфавиту. Среднее округляется только при выводе,
   до двух знаков после десятичной точки.

Формат строки города: `Tokyo, Japan +18 °C`.
Формат статистики: `Japan — 3 cities, avg: +19 °C, min: +16 °C, max: +22 °C`.
Это иллюстрация формата; реальные значения каждый раз запрашиваются у API.
Никакие температуры или итоговые показатели не заданы в коде.

HTTP 408, 429, 5xx и сетевые ошибки повторяются с паузами 1 и 2 секунды
при стандартных трёх попытках. Другие HTTP-ошибки и неверный JSON
выводятся сразу. Если город не удалось обработать, программа продолжает
работу с остальными, перечисляет пропущенные города и явно предупреждает,
что статистика неполная. Ошибки и диагностические сообщения идут в stderr,
погода и статистика — в stdout.

Коды завершения: `0` — все города обработаны; `1` — есть ошибки API;
`2` — ошибка входного файла или аргументов; `130` — прерывание пользователем.

## Проверка

```console
python -m unittest discover -s tests -v
```

Тесты не обращаются к интернету. Они проверяют удаление повторов,
чтение JSON, кодирование URL, повторные запросы, вычисление статистики
и поведение программы при частичной ошибке API.

Документация сервиса: [wttr.in](https://github.com/chubin/wttr.in#json-output).
